# Course Project Reflection: Core Data & UIKit Segues vs. Android MAD 1

In iOS development, Core Data acts as an integrated object graph management and persistence framework that handles relational modeling, faulting, and cascade deletion rules natively in-memory, whereas the local-storage approach in Mobile Application Development 1 (SQLite / Room) required manual SQL table drafting, explicit foreign-key constraints, and custom DAO queries. Navigation in UIKit using manual segues and `prepare(for:sender:)` facilitates direct, type-safe dependency injection where entire living `NSManagedObject` instances (such as `Subject` or `TaskItem`) are passed directly into the destination view controller's properties without serialization. In contrast, Android's `Intent` system relies on message-passing with `putExtra()` and `getStringExtra()`/`getParcelableExtra()`, requiring primitive serialization or `Parcelable` boilerplate and string-keyed unpacking that is prone to runtime key mismatches. Core Data with UIKit segues offers deeper object-graph continuity within a single process, while Android's Intent mechanism enforces strict component isolation across activity lifecycles.
